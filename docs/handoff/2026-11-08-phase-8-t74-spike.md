## Decisions made
These are the ADR-0014 choices; the owner has not reviewed them yet.
- **Host:** `localhost`. `BETTER_AUTH_URL` is set for each launch; the owner adds a desktop passkey.
- **GitHub sign-in:** a separate desktop OAuth app (**owner action**) and an auth window with no preload.
- **Media keys:** registered only while something is audible.
- **sherpa:** 2 threads, `silenceScale: 1`, `enableExternalBuffer: false`. The model gets a metadata-appended copy.
- **Electron:** fetched by our own script, with `path.txt` written.
- **ffmpeg:** pinned to BtbN's month-end LGPL build; only `ffmpeg.exe` is staged, and it is fetched in CI.
- **Locales:** `electronLanguages: ["en-US"]`.

## Things that surprised the spike (all in ADR-0014)
- **Electron 45:** has no `postinstall`. `require("electron")` runs `install.js` lazily if `path.txt` is missing.
- **electron-builder 26.18:**
  - dropped `app-builder-bin` and `7zip-bin`; it downloads its tools from GitHub with sha256 pins, and env vars can redirect those downloads;
  - 26.18.1 sits on the `v26` dist-tag, while `latest` still says 26.18.0.
- **sherpa 2.x:**
  - no espeak inside;
  - exits the process on a model without its metadata;
  - fails in Electron unless `enableExternalBuffer: false`.
- **Turbopack:** left one junction in standalone (`shiki-<hash>`).
- **BtbN:** deletes daily ffmpeg builds, so pin month-end builds.

## Known problems and risks
- **Not measured:**
  - GitHub OAuth on `localhost` (needs the desktop OAuth app);
  - a true cold boot (after a reboot);
  - the installer through real NSIS (sized with electron-builder's own 7-Zip at its settings instead);
  - WASM inside a Chromium worker (run in Node 24's V8 with the same `.wasm`; Chrome measured 0.382 in Phase 6, so the ratio is if anything understated);
  - media keys against Spotify specifically.
- The cold-start and RTF numbers used Electron 45.2.0; the pin is 45.2.1.
- `onnxruntime-node` was not installed (300 MB) and stays the fallback engine in the ADR.
