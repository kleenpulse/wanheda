## Bugs found

- **A release build from the shared checkout can swallow another session's uncommitted edits.** The first 0.7.3 installer was built in `D:\Vxrcel\wanheda` while another session edited `components/notes/` during `next build`; the bundle held a mix of old and new Notes code. It was deleted and rebuilt from a clean clone of the tag (`git clone` into a scratch folder, `node_modules`, `desktop/node_modules` and `desktop/.ffmpeg` copied in with robocopy, then `bun run desktop:build`). **Build installers from a clean clone whenever the checkout is shared.**

## Known problems and risks

- **Open, not reproduced:** the owner's preview of `d28e005` showed a floating island that took neither clicks nor drags. Four real-mouse runs of that same staged build passed. If it happens again: read `%APPDATA%\Wanheda Preview\logs\main.log` (the installed app doesn't write these lines: they are unpackaged-only) for `island:` lines. No "pointer is over it" line means main never sees the cursor there; that line without "drag begins" means the page never got the press. Untested guess: the island over an elevated or full-screen window.
- Prefs (older than this release, sharper now): a failed prefs read at shell load on a device with no prefs cookie, then any pref change, saves the defaults plus the patch, so Bench + Gold would overwrite a saved Ember. Either don't save while `load-failed`, or save only the patched field.
- Accounts whose prefs row already says `default` + null stay on Ember & Nebula, including rows made only by a reader or currency save. The owner was told; moving them needs a data update and the owner's yes.
- Still owed by the owner from T80: play `t80-test-eac3`, scrub, close, and look for a leftover `ffmpeg.exe` in Task Manager. If one is left, add the first-read watchdog (open T80 nit).
